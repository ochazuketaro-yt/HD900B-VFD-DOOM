# HD900B 前面 VFD の仕様メモ(実機で調べた内容)

HD900B の前面 VFD について、純正の DvdPlayer の逆解析と、実機での点灯確認から分かったことのメモです。
**[確認済み]** = 実機で動作を見て確認、**[推定]** = 逆解析やほかの観察からの推測です。HD900B 1 台での観察です。

## デバイス

- `/dev/venus_vfdo`(234,0)、`/dev/venus_vfd_wrctl`(234,1)、`/dev/venus_vfd_keypad`(234,2)、`/dev/venus_irrp`(234,50)。 **[確認済み]**
- 制御 IC は PT6302 系(DvdPlayer の `HMVFD_PT6302VFD` クラスが使われる)。TM1628 系ではありません。 **[確認済み]**

## 書き込みプロトコル

1 回の書き込み(交換)は次の手順です。 **[確認済み]**

```
write(vfdo,   &a, 4);
write(wrctl,  &b, 4);
poll: read(wrctl, &st, 4) until (st & 2)
```

- `ioctl(wrctl, 0x20007201)` はキーパッドの自動読み取りを停止し、`0x20007202` で再開します。更新の前後で必ず挟みます。
- 1 回の交換は約 7〜10 ms(`usleep` を使った場合)。ビジーポーリング(約 100 µs)にすると 1 ms 程度まで縮まります。このカーネルは HZ=100 のため、`usleep(1000)` は約 10 ms かかります。 **[確認済み]**

| 書き込み先 | `a` | `b` |
|---|---|---|
| 桁 i(0〜8)の文字コード | `(code << 8) \| (0x10 \| i)` | `0x1130` |
| アイコン i(16 バイト) | `(byte << 8) \| (0x30 \| i)` | `0x1130` |
| CG 文字 n(0〜4)の定義 | `0x20 \| n`(`b = 0x110`)のあとに、4 ワード(`b = 0x10`)と第 5 ワード(`b = 0x1010`) | |
| 確定 | `0x19` | `0x1130` |
| 表示オン | `0x70` | `0x1110` |

## 表示

- **9桁、各桁 5×7 ドット**。文字コードは ASCII − 0x10(`0x10` = 空白)。0x10〜0xFF は ROM のフォント(ASCII・カナ・図形)、0x00〜0x0F は CG 領域。 **[確認済み]**
- **CG 文字**: 5 バイト = 5 列(左→右)、各バイトのビット 0 が最上段。上 5 ビットだけでなく、**7 行すべて**使えます。 **[確認済み]**
- **自由に使える CG は 4 種類(コード 1〜4)**。コード 0 の CG は下部の記号 RAM と共有で、書くと下部のバーが点灯します。 **[確認済み]**
- 同時に任意の絵にできる桁は 4 桁です。9 桁すべてを任意のドットにするには、時間多重(`vfdmux` のグループ表示)が必要です。 **[確認済み]**

### 時間多重(`vfdmux`)

桁をグループ(0〜3、4〜7、8)に分け、サブフレームごとに「他グループの桁を空白にして、CG1〜4 を再定義して、桁を表示」を繰り返します。

| グループ数 | 列数 | 結果(目視) |
|---|---|---|
| 1 | 20 | ちらつきなし。最も見やすい(本プロジェクトの既定) |
| 2 | 40 | ちらつきは許容範囲だが、20 列のほうが読みやすい |
| 3 | 45 | ちらつきあり。明るさは約 1/3 |

- 暗い面(dim)は、交互のパスで点灯させて約 50% のグレーにしています(1 グループのとき、ちらつきは目立ちません)。
- 表示の「反応の遅さ」を利用した擬似的な階調として動作します。 **[確認済み(目視)]**

### 記号 RAM(下部バー・アイコン) **[確認済み(目視)]**

CG 文字 0 の 5 バイト(`0x20` のあとに送る 5 バイト)が記号 RAM に対応します。

- ビット 3/4/5: 下部バーのブロック。ブロック番号 = 5 × (ビット − 3) + バイト(0〜13 の 14 ブロック、ビット 5・バイト 4 は音符アイコン)。
- ビット 6: アイコン(バイト 0〜4 = ビデオ / 写真 / USB / フォルダ / LAN)。
- ビット 7: アイコン(バイト 0〜4 = IE / 一時停止 / 再生 / 巻戻し / 早送り)。
- 全ブロック・全アイコンが `1f` の 5 バイトで点灯するなど、バーの点灯規則には**未解明の点**が残っています。

### 上段のアイコン(`sym[i]`、16 バイト)

- ビット 0 = 上段アイコン(APE / DTS / MP3 / アンテナ / 時計 / REC / 1080P / 24P など)、ビット 1 = コロン。ビット 2〜7 と `sym[9..15]` は、目視で反応が見つかりませんでした。 **[確認済み]**

## 時計・時刻

- この端末では `gettimeofday()` が最初の呼び出しの値で固まります。`time()` / `clock_gettime()` も 1 秒刻みで不安定です。 **[確認済み]**
- 信頼できるのは `times()`(100 Hz)と `/proc/uptime` です。fbDOOM の時間取得は `times()` に切り替えています。
- `src/tools/tt.c` で確認できます。

## 入力 **[確認済み]**

- USB キーボードは `/dev/input/eventN`(evdev)から読めます。押下(value=1)と離す(value=0)が取れ、リピート(value=2)は無視しています。
- リモコンは `venus_IR_input`(`event0`)で、押した瞬間に押下と離すが同時に届き、押している時間は取れません。
- 同じキーが純正の DvdPlayer にも届く可能性があります(DvdPlayer は `/dev/tty0`、`/dev/venus_irrp`、`/dev/venus_vfd_keypad` を開いています)。
