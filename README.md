# hd900b-vfd-doom

**2011 年発売のメディアプレーヤー HiMedia HD900B(Realtek RTD1186)の前面パネルの小さな VFD(9桁 × 5×7ドット = 45×7ドット)で、DOOM を動かすデモです。**

DOOM(fbDOOM をベースにした Linux 版)を HD900B の中で実行し、ゲームの内部情報(マップの壁・敵・自機)を **20列 × 7行のドットに描き直して**、前面の VFD に表示します。


> ⚠️ **非公式・自己責任のプロジェクトです。** プレーヤーの前面 VFD コントローラを、純正ファームウェア(DvdPlayer)とは別のプロセスから直接叩きます。
> 動作確認は **HD900B 1台のみ**です。[免責](#免責)を必ずお読みください。
>
> **DOOM のデータ(WAD)は含まれません。** 正規に入手した `DOOM.WAD`(または `DOOM1.WAD`)を、ご自身で用意してください。

## できること

- 起動時に **DOOM ロゴ**(20×7ドットで描いた画像)を数秒表示 → **メニュー**(`ORIG` / `WAVE` / `FREE` / `EXIT`)→ ゲーム開始(E1M1)。
- 前面 VFD に、**壁の輪郭**(距離に応じて高さが変わる)、**敵**(2列の棒が高速で点滅し、遠いほど低く表示)、**自機の銃**、**発砲時の全面フラッシュ**を表示します。
- 下部の **14ブロックのバー** を体力表示に使います。
- **エイムアシスト**(照準の近くにいる敵へ視点が少し寄ります)があります。
- DOOM 標準のオープニングデモ(`demo`)や、自動操縦モード(`auto`)も選べます(キー入力不要)。

メニューの各モード:

| 項目 | 内容 |
|---|---|
| `ORIG` | 元の DOOM どおり。体力が減り、下部バーが減ります。 |
| `WAVE` | 無敵。自機の前方にゾンビが出続けます。 |
| `FREE` | 無敵。敵の追加はありません(自由に歩き回れます)。 |
| `EXIT` | 終了して、表示を `HD900B` に戻します。 |

## 動作確認環境

| 項目 | 内容 |
|---|---|
| 端末 | **HiMedia HD900B** |
| SoC | Realtek **RTD1186**(MIPS 24Kc、FPU 内蔵) |
| OS | Linux 2.6.34-VENUS(Realtek SDK ファームウェア、2011 年ビルド) |
| 接続 | 有線 LAN、Telnet(`root`、パスワード空)で操作可能なこと |
| 入力 | USB キーボード(Logitech 受信機のキーボードで確認) |
| PC(インストール時のみ) | Python 3.8 以降(標準ライブラリのみ)。Debian Linux で確認、macOS/Windows は未確認 |

HD900B 以外の機種では確認していません([`docs/COMPATIBILITY.md`](docs/COMPATIBILITY.md))。

## 準備するもの

1. HD900B 本体(LAN に接続、Telnet が使えること)と、USB キーボード
2. インストール用の PC(Python 3.8+)
3. **ご自身で用意した `DOOM.WAD`**(正規に入手したもの。本プロジェクトには含まれません)

## インストール

`dist/` にビルド済みのバイナリが入っています(静的リンクの MIPS32 実行ファイル。[`build/build.sh`](docs/BUILD.md) で再ビルドもできます)。

```sh
python3 tools/install.py --host <プレーヤーのIP> --wad /path/to/DOOM.WAD
```

- プレーヤー側の `/tmp/vfd` にファイルを置きます。**ファームウェア(フラッシュ)・`/system`・`/data` は一切変更しません。** `/tmp` は RAM なので、電源を入れ直すと消えます(その場合はインストーラをもう一度実行します)。
- すでにプレーヤー上に WAD がある場合は、`--wad /path` の代わりに `--wad-on-device /プレーヤー上のパス/DOOM.WAD` で、リンクを張れます。
- ファイルの SHA-256 を照合して、一致しなければ中止します。

## 使い方

Telnet でプレーヤーに入って実行します。

```sh
cd /tmp/vfd
./doomvfd.sh              # メニュー付きで起動(既定)
./doomvfd.sh demo         # オープニングデモ(demo2 / demo3 もあります)
./doomvfd.sh auto         # 自動操縦(入力なし)
```

起動後、DOOM のロードを待って(数秒)から、前面 VFD に表示されます。TV の画面は、そのまま純正のホームです(TV には何も出しません)。

### キー操作

| 場面 | キー | 動作 |
|---|---|---|
| メニュー | `W` / `S`(`↑` / `↓`) | 項目の切り替え |
| メニュー | テンキー `0`(`Enter`) | 決定(新規ゲーム開始、または終了) |
| ゲーム中 | テンキー `1` | メニューを開く(ゲームは一時停止。もう一度 `1` で戻る) |
| ゲーム中 | `W` / `S` | 前進 / 後退 |
| ゲーム中 | `A` / `D` | 左 / 右に旋回 |
| ゲーム中 | `Ctrl` またはテンキー `0` | 射撃 |
| ゲーム中 | `Space` | ドアを開ける(使う) |
| ゲーム中 | `Shift` | 走る |
| ゲーム中 | `Alt` | 横移動(旋回キーと併用) |
| いつでも | `Backspace` | 終了 |

- 矢印キー、テンキーの `8` `2` `4` `6` も移動・旋回に使えます。
- テンキーは NumLock の状態に関係なく、同じキーとして扱われます。
- キーの入力は `/dev/input/eventN` から直接読みます。**同じキーが純正のホーム画面(DvdPlayer)にも届く可能性があります。** WASD とテンキーで操作して、ホームの操作と干渉しないことを確認しています(矢印キーなど、ほかのキーは未確認です)。
- キーボードの `event` 番号が違う場合は、`./find_keyboard.sh` で確認して `EVDEV=/dev/input/eventN ./doomvfd.sh` で指定します。

環境変数(`doomvfd.sh`): `WAD`(WAD のパス)、`EVDEV`(入力デバイス)、`BLINK`(敵の点滅の半周期、10ms 単位。既定 1 = 約 50Hz)。

## 終了と元に戻し方

- ゲームの終了: メニューの `EXIT`、`Backspace`、または別の Telnet から `/tmp/vfd/vfd_stop.sh`。終了すると、前面の表示は `HD900B` に戻ります。
- 完全に消す: `/tmp/vfd/uninstall.sh`(プロセスを止めて表示を戻し、`/tmp/vfd` を削除します)。
- 異常終了などで表示が戻らない場合: `/tmp/vfd/vfdctl pt HD900B`。それでも戻らなければ、電源を入れ直してください(`/tmp` は消えます)。

## 仕組み(概要)

```
 USBキーボード ─▶ /dev/input/eventN ─▶ fbdoom_vfd ──(DOOMのゲーム状態)──▶ 20x7ドットへ描き直し
                                            │  /tmp/vfd/frame (140 バイト)
                                            ▼
                                        vfdmux ──▶ /dev/venus_vfdo, /dev/venus_vfd_wrctl ──▶ 前面VFD
```

- **描画**: DOOM の画面を縮小せず、マップの壁(線分)に 20 本の光線を飛ばして距離を測り、壁の上端・下端の「輪郭線」と段差の縦線を描きます。敵・自機の銃・フラッシュ・体力は、別のルールで描き足します。
- **VFD の制御**: 9桁の各桁は 5×7 ドットで、任意の絵にできる文字(CG 文字)は 4 種類です。4 桁を `CG1`〜`CG4` に割り当てて **20列を時間多重なし**で表示します(桁を増やすと、ちらつきが出るため)。
- **グレー**: 暗い面は交互のパスで点灯させ、約 50% の明るさにしています。
- **敵の点滅**: 専用の面を `vfdmux` が `times()`(10ms 単位)で反転します。
- **体力バー**: 前面下部の 14 ブロックのバーを、記号 RAM(CG 文字 0 と共有)で制御します。

詳しくは [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) と [`docs/VFD-NOTES.md`](docs/VFD-NOTES.md)(実機で調べた VFD の仕様メモ)を参照してください。

## 制限事項

- 表示は **20列 × 7行** です。敵や壁の見分けは、見慣れるまで難しいです。
- 音は出ません(`-nosound`)。新規ゲームは E1M1、難易度は固定(中)です。
- リモコンでの操作は未対応です(リモコンのキーは「押した瞬間」のパルスとして届くため、押しっぱなしの移動に向きません)。
- 前面のキーパッドの自動読み取りを、実行中は停止します(終了時に元に戻します)。強制終了(`kill -9`)した場合は、`vfdctl pt HD900B` や電源の入れ直しで戻してください。
- この機器の `gettimeofday()` は値が進みません。時間は `times()` で取っています(ゲームの速度は実時間に合っています)。
- 動作確認は HD900B 1 台のみです。

[`docs/BUILD.md`](docs/BUILD.md) を参照してください。Bootlin の MIPS32el(uClibc-ng)ツールチェーンを取得して、`build/build.sh` を実行すると `dist/` に生成されます。

## リポジトリの構成

```
src/fbdoom/    fbDOOM(GPL-2.0-or-later)に VFD 描画・evdev 入力・ロゴ/メニューを追加したもの
src/tools/     vfdmux(VFD の時間多重表示)/ vfdctl(VFD の簡易制御)/ evlog(キー入力ログ)/ tt(時計の確認)
device/        プレーヤー側のスクリプト(doomvfd.sh など)
tools/         PC 側のインストーラ(install.py)と Telnet ヘルパ
build/         ビルドスクリプト(ツールチェーンの取得と検証を含む)
dist/          ビルド済みバイナリ + SHA256SUMS
patches/       元の fbDOOM に対する差分(変更箇所の確認用)
docs/          ARCHITECTURE / VFD-NOTES / BUILD / TROUBLESHOOTING / COMPATIBILITY
licenses/      GPL-2.0 / LGPL-2.1 の全文
```
