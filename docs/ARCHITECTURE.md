# アーキテクチャ

## 全体

```
 fbdoom_vfd(DOOM 本体 + VFD 描画 + 入力 + ロゴ/メニュー)
   ├─ 入力: /dev/input/eventN(evdev)を毎フレーム読み、DOOM のキーイベントに変換
   ├─ 描画: ゲーム状態(マップ・敵・自機)から 20x7 ドットのフレームを作る
   └─ 出力: $FBDOOM_VFD(既定 <dir>/frame)へ 140 バイトを pwrite

 vfdmux(別プロセス)
   └─ frame を高速に読み返し、VFD の 4 桁を時間多重なしで更新

 doomvfd.sh   両者を起動し、終了時に vfdctl で "HD900B" の表示に戻す
```

DOOM 本体は framebuffer(`/dev/graphics/fb0`)を使いません(`FBDOOM_NOFB=1`)。HDMI の画面は純正のままです。

## フレームファイル(140 バイト)

| オフセット | 内容 |
|---|---|
| 0〜44 | 暗い面(dim)。`vfdmux` が交互のパスで点灯 → 約 50% の明るさ。 |
| 45〜89 | 明るい面(bright)。常に点灯。 |
| 90〜134 | 点滅面。`vfdmux` が `times()` で `VFD_BLINK` × 10 ms ごとに反転(敵の点滅)。 |
| 135〜139 | 記号 RAM 5 バイト(下部バー)。変化したときだけ CG 文字 0 として書く。 |

各バイトが 1 列で、ビット 0 が最上段、ビット 6 が最下段です。このゲームは 20 列だけ使います(0〜19)。

## 描画(`src/fbdoom/i_video_fbdev.c`)

- **壁**: 20 本の光線(視野 90°)をマップの線分に飛ばし、最短距離を測ります。通行できる両面の線(段差が 24 以下で、天井との間が 56 以上)は壁として扱いません。壁の上端と下端の輪郭を、距離を対数で写した高さで描き、距離が大きく変わる列の間に縦線を足します。
- **敵**: 視界内で、手前の壁に隠れていない敵を、2 列幅の棒として描きます。高さは距離に応じて 1〜6 行で、点滅面に描きます。
- **自機の銃**: 下 2 行に、中央の 3 列で描きます。発砲時(DOOM のマズルフラッシュのスプライトが出ている最初の 4 tic)は、全面を点灯します。
- **体力**: 下部の 14 ブロックのバー(`FBDOOM_HUD=1`)。
- **エイムアシスト**(`FBDOOM_ASSIST=1`): 照準から約 12° 以内の敵のうち最も照準に近いものへ、毎フレーム角度差の 20% だけ視点を寄せます。
- **ロゴ**(`FBDOOM_UI=1`): 20×7 のビットマップ(`#` = 明、`+` = 暗)を左からワイプ表示 → 点滅 → 保持。下部バーが同時に伸びます。
- **メニュー**: 4 桁に収まる 4 文字の項目(ORIG / WAVE / FREE / EXIT)。W/S で切り替え、決定でモードを設定して新規ゲームを開始します(`G_DeferedInitNew`)。メニュー中は `paused` でゲームを止めます。

## モード

- `vfd_god`(無敵)と `vfd_spawn`(ゾンビの追加出現)は、実行時の変数です。メニューで決定すると、ORIG = (0,0)、WAVE = (1,1)、FREE = (1,0) に設定されます。
- 環境変数での初期値: `FBDOOM_GOD`、`FBDOOM_NOSPAWN`、`FBDOOM_AUTO`(自動操縦)。

## 環境変数(`fbdoom_vfd`)

| 変数 | 意味 |
|---|---|
| `FBDOOM_VFD` | フレームファイルの出力先 |
| `FBDOOM_NOFB` | 1 で framebuffer を使わない |
| `FBDOOM_RAY` | 1 でレイキャストの描画(0/未設定は画像を縮小する旧方式) |
| `FBDOOM_STYLE` | 壁の描き方。`G`(既定の使い方、対数の高さ)、`B`(線形)、`D`(レーダー)、`A`(塗りつぶし) |
| `FBDOOM_COLS` | 描画する列数(20 = 時間多重なし、40、45) |
| `FBDOOM_EVDEV` / `FBDOOM_GRAB` | 入力デバイス / `EVIOCGRAB` |
| `FBDOOM_UI` / `FBDOOM_HUD` / `FBDOOM_ASSIST` | ロゴ+メニュー / 体力バー / エイムアシスト |
| `FBDOOM_GOD` / `FBDOOM_NOSPAWN` / `FBDOOM_AUTO` | 無敵 / ゾンビを出さない / 自動操縦 |
| `FBDOOM_STAT` / `FBDOOM_DBG` / `FBDOOM_DIST` | デバッグ出力(標準エラー) |

## 設計上の判断

- ゲーム画像を縮小してコントラストを調整する方式は、45×7 では判別が難しかったため、ゲームの内部情報から描き直す方式にしました。
- 面で明るく光らせる方式(塗りつぶし)は、時間多重のちらつきが目立ちました。輪郭線だけ(細い線)にして、ちらつきを避けました。
- 時間多重(グループ数 2〜3)で列数を増やすより、20 列のちらつきなしのほうが見やすかったため、20 列を既定にしています。
